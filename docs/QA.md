# 実機QAチェックリスト (M19)

このリポジトリの開発環境 (headless Chromium 上の Playwright) では検証できない、
本当に実機でしか確認できない項目だけをまとめる。

> **注意**: レイアウト崩れの類は「実機でしか分からない」と誤解しがちだが、
> M15.5 では 390px ビューポートの水平オーバーフロー、M15.7 ではキャンバスの
> 実表示サイズ (0×0 崩れ) を headless の数値検査で検出・再発防止できた。
> 新しい問題を見つけたら、まず「headless で数値化できないか」を検討してから
> このリストに足すこと。

## iOS Safari

- [ ] safe-area (ノッチ・ホームインジケータ) と下部ツールバーが重ならない。
      `env(safe-area-inset-*)` を使っている箇所 (`style.css` の
      `#mobile-toolbar`, ドロワー等) が実機の切り欠きで正しくパディングされるか。
- [ ] PWA としてホーム画面に追加できる (`Manifest` の `display: standalone` が
      実際にステータスバーなしで起動するか)。
- [ ] オフライン起動 (機内モードで一度開いたあとアプリを起動し直す)。
- [ ] 2本指ピンチによるズームが、ブラウザ標準のページズームと競合しない
      (`touch-action: none` が Safari でも効いているか)。
- [ ] 環境音 (WebAudio) が自動再生制限に引っかからず、ユーザー操作後に
      正しく鳴り始める。
- [ ] ホームバーの上にドロワー/モーダルのボタンが隠れない。

## Android Chrome

- [ ] 上記 iOS の項目と同様 (safe-area, PWA インストール, オフライン起動,
      ピンチ, 環境音)。
- [ ] 「ホーム画面に追加」バナー/プロンプトが意図したタイミングで出る
      (出すぎる/全く出ない場合は `manifest.json` を見直す)。
- [ ] 戻るボタン (ジェスチャー/物理ボタン) でドロワーやモーダルが自然に閉じる
      (もしくは意図せずページ全体が閉じない)。

## 共通

- [ ] `?debug` の perf HUD で **3ms/frame 以内** を実機でも確認する
      (headless の計測値は実機の非力な GPU/CPU を代表しない)。
- [ ] 低速回線 (Slow 3G 相当) での初回ロード体験。Service Worker の
      キャッシュが効いた2回目以降の起動が速いか。
- [ ] 長時間 (30分以上) のバックグラウンド放置後、タブ復帰時に sim が
      暴走せず (借金上限が効いて) 穏やかに追いつくか。

## 発見された問題の扱い

このリストの項目で問題が見つかった場合:

1. まず「headless の e2e で検知できる数値検査に落とし込めないか」を検討する
   (例: レイアウト崩れ → `scrollWidth`/`boundingBox`、パフォーマンス → perf HUD の
   出力を assertion 化)。
2. 検知できない場合のみ、このファイルにチェック手順として残す。
3. 修正は該当マイルストーン (またはこの QA チェックの実施回) の一部として行う。
