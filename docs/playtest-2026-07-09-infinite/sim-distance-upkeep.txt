# M30 距離のコスト勾配 (distanceUpkeep) の before/after 実測 (2026-07-10)
#
# 手法: 出荷構成相当 (Game(1234, 'wildland') 直接駆動 = applyGenome(PETRI_PARAMS,
#       genome) + wildland paramOverrides (M29-B の休眠/evict/横芽抑制込み)。
#       BATCH=12 tick で 24,000 tick (= Day 100 相当) 駆動し 5日おきにサンプリング。
#       ハーネス: scratchpad/sim-distance.mjs。すべて同一 seed=1234。
# before = distanceUpkeep 無効 (K=0、= M29-B 出荷そのまま)。
# after  = distanceUpkeep=K, distanceUpdateInterval=60 を上乗せしただけ。
#
# 列: span = ノード bbox の長辺。live/evicted/touched = 実体/圧縮解放済み/累計チャンク。
#     dormant = 休眠セル数。frozen = 中点が休眠セルにあるエッジ数。
#     maxHop = 母体連結成分の最大 hop。nearFat/farFat = 母体連結成分の
#              h<=10 / h>=0.7*maxHop のエッジ平均 fatigue (null = そのバケツが空)。
#     ×24 の tick 予算は 25ms/tick。
#
# ── 推奨値 ──────────────────────────────────────────────
#   distanceUpkeep         = 0.005
#   distanceUpdateInterval = 60
#
# ── 結論 (数字の根拠) ───────────────────────────────────
# (1) 近傍 vs 遠端の fatigue に測定可能な差が出る: 母体連結成分で
#     nearFat ≈ 0.27, farFat = 0.327 (+21%) を Day 20 以降ずっと維持
#     (対照の単体テスト test/distance-upkeep.test.ts でも 30hop 一本鎖で
#      遠端 fatigue > 近傍 + 0.5 を bit で固定)。
# (2) span の成長ペースは budget 内: Day 40 で 613.1 → 493.7 (-19.5%、2割減の
#     許容内)。しかもこの落ち込みは序盤の一過性で、Day 60 以降は逆転し
#     Day 100 で 660.6 → 727.6 (+10%)。
# (3) ★ M29-B の既知の限界「span が Day 50 以降 660 で停滞」を解消: before は
#     Day 50〜100 を通して span 660.6 で完全に頭打ちだが、after は 657→727 と
#     伸び続ける。内向きの稠密化/backfill が距離コストで抑えられ、配分が前線へ
#     回るため (M29-B の横芽抑制と同じ機序が距離方向にも効く)。
# (4) tick コストは悪化しない: 距離 BFS は flux のマルチソース BFS に便乗する
#     ので追加走査ゼロ。Day 100 で 16.7ms/tick (before 17.8ms/tick) と誤差内。
#
# ── ★ 重要な限界 (M30-B へ申し送り) ────────────────────
# 母体 (source) からの「グラフ hop 距離」は、原野では前線のごく一部しか
# カバーしない。forager reclaim の前線は時間とともに母体から切り離される:
#   連結成分の到達ノード数 / 全ノード数 (scratchpad/diag-connect.mjs, seed 1234):
#     Day 5:  160 / 278  (maxHop 27、連結成分 span 91 / 全 span 250)
#     Day 40:  17 / 2045 (maxHop  7、連結成分 span 29 / 全 span 451)
#     Day 80:   7 / 2380 (maxHop  2、連結成分 span 12 / 全 span 525)
# = 遠征している前線はほぼ孤立成分で、source から到達できない → sourceHops に
#   載らない → 距離ペナルティが掛からない。つまり distanceUpkeep が効くのは
#   「母体に繋がったまま伸びる序盤の連結コア」であって、切り離された遠征前線
#   ではない。このため:
#   - 「伸びすぎた遠征枝が枯れて戻る」は連結コアでは起きるが、支配的な孤立
#     前線では起きない (期待した凍結グラフの頭打ちにはならない —
#     frozen エッジは Day 100 で 2594 → 2854 と before より減っていない。
#     span/edges が増えた分に比例)。
#   - hop 距離ではなく「母体位置からのユークリッド距離」で測れば孤立前線にも
#     効かせられる。M30-B でバイオームと配線する際は、この距離定義の見直しを
#     推奨 (flux BFS 便乗をやめ、各ノード pos と source pos の距離を
#     distanceUpdateInterval ごとにキャッシュする形。RNG 不使用・決定論は維持可)。
#
# ── 休眠 (M29) との整合 (確認済み) ──────────────────────
# - 休眠エッジも flux BFS には参加し続ける (updateFlux は全エッジ対象) ので、
#   休眠領域を貫く連結路の hop 距離は古びない。「休眠中は距離が古くて構わない」
#   以前に、そもそも古びない。
# - 休眠エッジは life.ts の状態更新ごとスキップされる (M29) ため、距離ペナルティ
#   の fatigue 加算も掛からない = 「休眠中は消耗も凍結」と自動的に整合する。
#   起床すれば次 tick から距離ペナルティ込みで再開する。
#
# ── パラメタ振りの要約 (Day 40, span / 対 before) ──────
#   K=0     : span 613.1 (基準)            — before
#   K=0.002 : span 613.1 (±0)              — 弱すぎ (成長判定を変えず bit 一致で不発)
#   K=0.005 : span 493.7 (-19.5%)          — 採用 (差が出て budget 内)
#   K=0.01  : span 472.5 (-23%)            — 却下 (2割超)
#   K=0.02  : span 467.6 (-24%)            — 却下 (2割超)
