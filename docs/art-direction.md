# アートディレクション — M16.5 絵作りパス

> モックアップの狙い: 「苔むした岩肌・木漏れ日の中を、金色に光る網が這う」。
> 実プレイ検証 (2026-07-05) で現状との差分を実測した結果を反映する
> (証跡: `docs/playtest-2026-07-05/`)。このドキュメントは M16.5 着手前の
> 基準画としてまとめ、実装後は本ファイルの色票がそのまま `render.ts` の
> 定数と対応する。

## 要素別 現状 → 目標 (2026-07-05 実測)

| 要素 | 現状 (M16.5 着手前) | 目標 (モックアップ) |
| --- | --- | --- |
| 背景/地形 | ほぼ黒 (`STAGE_BG` ≈ `#0b0d0c`)。バイオームが識別できず、皿も大陸も「夜の虚無」に見える | 苔の緑 (`#4a5d3a`〜`#6b7d4a`)、土と岩の暖グレー、木漏れ日の暖色。昼は明るい自然のフィールド |
| Biomass 膜 | 均一なカーキ (`#c9b87a` 付近) のぼかしブロブ。中心が最も不透明・明るく、縁は暗い → 「広がっている」実感が薄い | 半透明の金 (`#e8b84b` 系)。成長前線の縁が明るくリム発光し、内側 (確立した核) は下の地形が透ける |
| ネットワーク | 赤茶 (`#c4732b` 付近) の均一な実線。光っていない | 金色に発光する脈。activity (flux) が高いほど明るく、節点は光の粒 |
| ノード/拠点 | 緑の光点は既にモックアップに近い。拠点は無地の色ドット | 光る粒はこの方向で強化 |
| 障害物 (石) | グレーのぼかし塊、質感なし | 陰影とエッジのある岩 (まだらノイズ) |
| 水域 | フラットな青ベタ (大陸) | 深みのあるグラデーション + 縁の明るいライン |

## 実装した配色 (`render.ts`)

### 地形の下地 (`STAGE_BG.inner`、昼想定)

| ステージ | 色 | 意図 |
| --- | --- | --- |
| 皿 | `rgb(88,104,64)` | 苔の緑 |
| 洞窟 | `rgb(46,54,68)` | 冷たい岩肌。地下の閉空間らしさを保つため他より暗いままにする (唯一の例外) |
| 砂漠 | `rgb(128,100,62)` | 陽だまりの砂 |
| 都市跡 | `rgb(112,96,74)` | 風化した石材 |
| 湿地 | `rgb(70,96,78)` | 湿った苔 |
| 大陸 | `rgb(78,94,86)` | 海沿いの陸地 |

いずれも「素の地面」(他のどの場レイヤーにも該当しないセル) に、`hashNoise()`
(整数座標だけで決まる安い決定的疑似乱数) を明度に乗せた苔の粒ノイズを
常時敷く。これが無いと STAGE_BG がそのまま均一に見えてしまい、旧配色の
「虚無」感の一因になっていた。

### Biomass 膜のリム発光

sim の性質上、`v = raw/maxBio` は「生まれたて (低) → 成長前線 (中) →
確立した核 (高)」の順に大きくなる。旧実装はこの `v` に単調増加するアルファ
(中心ほど不透明) を割り当てていたが、新実装は `k≈0.32` (成長前線) を頂点に
したガウス状の山でアルファをピークさせ、核に近づくほどアルファを絞る。
「成長前線が光り、確立した核は下地が透ける」というモックアップの狙いに
直接対応する。

- `PLASMA_FRINGE` `rgb(150,120,45)` — 生まれたての縁
- `PLASMA_RIM` `rgb(255,224,120)` — 成長前線 (最も明るいリム)
- `PLASMA_CORE` `rgb(205,165,90)` — 確立した核 (低アルファ)

### ネットワークの発光

エッジ描画を2パス化: 太いぼかし下層 (`globalCompositeOperation: 'lighter'`、
`TUBE_GLOW` `rgb(255,200,90)`) + 細い明色の芯 (`TUBE_LIGHT`/`TUBE_DARK`)。
activity (flux) が高いエッジほど glow の幅とアルファが大きくなる。
エッジ総数が `GLOW_MAX_EDGES` (1200) を超えるフレームは glow パスを省略する
性能フォールバック付き (3ms/frame 予算を守るため)。

### 障害物・水域の質感

- 障害物: `STAGE_ROCK_COLOR` に `hashNoise()` ベースのまだら (明度 ×0.72〜1.27)
  を乗せ、「陰影とエッジのある岩」に近づける。
- 水域 (大陸): `WATER_BODY_SHALLOW` → `WATER_BODY_DEEP` のグラデーション
  (揺らぎノイズで深浅を演出) + 縁 (`wb` が 0.5〜0.62 の帯) を `WATER_EDGE_COLOR`
  の明るいラインにする。

### 昼夜のトーン

旧実装は不透明の暗紺 (`rgba(6,10,20,nightFactor*0.4)`) を単純に上塗りし、
フル `nightFactor` で画面全体が真っ黒に近くなっていた
(`globalCompositeOperation: 'color'` を使った初期実装は逆に「彩度を完全に
青へ置き換えてしまい画面全体が単色の青になる」という別の失敗をした —
screenshot 検証で発覚し、単純な半透明の青の source-over 重ねに差し替えた)。
新実装は `rgba(35,55,100,nightFactor*0.30)` の弱い半透明の青を重ねるだけに
し、フル nightFactor でも元の色相 (苔の緑・金のプラズマ) が透けて残る。

## 性能

`?debug` の perf HUD で計測 (このサンドボックス環境、皿/大陸ステージ・
速度×24・成長中):

| 状態 | draw (目安) |
| --- | --- |
| M16.5 着手前 | 2.2〜2.3ms |
| M16.5 適用後 (最適化後) | 2.7〜3.3ms |

3ms/frame 予算に対してほぼ収まる範囲 (このサンドボックスの CPU は
ノイズが大きく、着手前でも 60fps を安定して出せていない — 目標ハードウェア
そのものではない点に注意)。地形の粒ノイズは dirty な全セルで必ず通る
唯一の追加コストなので、配列アロケーションを避けて乗算のみで済ませる形に
インライン化した。ネットワークの glow はエッジ総数ベースの
フォールバック (`GLOW_MAX_EDGES`) を持つ。

## 検証

- `e2e/visual.spec.ts` — 画面隅 (まだ生物が届いていない領域) の輝度が
  旧配色の水準 (実測 ≈7.5) まで退行していないことを検査する回帰ガード。
  実際のピクセル比較 (`toHaveScreenshot`) は、CI がフレッシュにインストールする
  Chromium とこのサンドボックスの `/opt/pw-browsers/chromium` とでラスタライズが
  微妙に異なりうるため採用しなかった。
- 固定シードではなく `new Game()` の既定 (ランダムシード) のまま検査している。
  地形特徴 (石/水/毒素) がどれも旧 `STAGE_BG` よりずっと明るいため、
  たまたま隅に来ても「ほぼ黒」への退行検知は揺らがない。
